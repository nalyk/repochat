## CONCESSIONS (final text — accept means this wording goes into the implementation contract)
C1 (D4) Descriptor-verified no-follow traversal: every path component is Lstat'ed (must be a real directory), opened

   Lstat as a regular file, is opened O_NOFOLLOW|O_NONBLOCK, then fstat'ed: regular + SameFile. Symlinks are never
   followed anywhere (listed as symlinks, content not served). Same routine for `.repochatignore`. Before each fileset
   refresh the root path is re-stat'ed and compared (SameFile) with the held os.Root; mismatch → fail closed.
C2 (D6) Git hardening additions: every git invocation uses explicit `--git-dir=<abs>` and `--work-tree=<root>` (root =
   nearest ancestor containing `.git`, found by repochat itself, so `core.worktree` cannot redirect);
   `GIT_NO_LAZY_FETCH=1`; `GIT_ALLOW_PROTOCOL` set to a deny-all value (tested on the installed git with a positive
   control: promisor remote using ext:: + missing object must run the marker WITHOUT protections and must NOT with them);

   hostile-.git isolation: repo-local config is treated as untrusted for execution as defense in depth, "not a sandbox".
C3 (M1) Empty authorization never widens: diffs are produced per authorized file (one literal pathspec each); zero

   enumeration is all-or-error (a capped/failed enumeration is an error). A file pathspec P is skipped when any changed
   entry under `P/` is withheld (file↔directory type change), so a literal pathspec can never pull in withheld content.
   Regression test: commit touching only credentials.json.
C4 (M2) Search matches the DISCLOSED representation: when redaction is on, a file that may contain secret spans is
   redacted first and the predicate runs on the redacted lines; hidden bytes cannot change match existence, counts or

   tool error); with `--no-redact` it runs with --name-only and commits are reported only if an authorized path matched.
C5 (M6) Authorized history = commits reachable from HEAD, refs/heads, refs/remotes, refs/tags. After resolving a
   revision to a commit SHA, reachability is checked (`for-each-ref --contains` / `merge-base --is-ancestor HEAD`);
   reflog syntax (`@{`) and stash are rejected; unreachable/dangling objects are not served. Path policy applies to

C6 (D2/D3/Q2) Two universes: (a) working tree = `git ls-files` (tracked incl. tracked-but-gitignored, plus untracked

## DISAGREEMENTS (each with my compromise)
X1 (D6 "disable system/global config") Reject. System + global config is git's own "protected configuration" and is
   the user's; disabling it breaks `core.excludesFile` (which would EXPOSE more untracked files), `core.autocrlf`
   (spurious modifications) and `safe.directory`. Compromise: keep them, but neutralise every execution-capable key
   from ANY scope with command-scope overrides/flags (fsmonitor, hooksPath, pager, diff.external, textconv, ext-diff,
   showSignature, all filter.*.clean|smudge|process|required), which outrank all config files; documented trust
   boundary: user/system config trusted, repo-local config untrusted for execution.
X2 (D6 "prefer raw-object plumbing") Partly. Plumbing for object access (cat-file, ls-tree, diff-tree, rev-list,
   for-each-ref, ls-files). Porcelain `git status` / `git diff` only for working-tree comparisons, because plumbing
   diff-files/diff-index needs an index refresh (a write) to avoid stat-dirty false positives. They run with
   --no-ext-diff --no-textconv, GIT_OPTIONAL_LOCKS=0 and neutralised filters, proven by positive-control fixtures.
X3 (D7 structuredContent) Reject. Unknown clients may forward ONLY structuredContent to the model and drop the text,
   and K7 prevents verifying ChatGPT's behaviour. Compromise: every tool result ends with one stable, documented,
   tested line `@meta {json}` carrying tool, repo id, rev (if any), generation, complete, truncated, next cursor /
   next_start_line, redactions, withheld counts.
X4 (D9 EOF) Counter. On stdin EOF: stop admitting, let already-admitted calls finish within a bounded 5 s drain, then
   exit (needed for pipe-driven use: `printf … | repochat mcp`, doctor, `repochat call`). ctx cancel / writer failure →
   immediate exit.
X5 (D10 args) Split. Persistent audit JSONL is metadata-only by default (accept), `--audit-args` opts in. The
   ephemeral live terminal line DOES show tool + sanitized, redacted, length-capped arguments (path, query) because
   showing the user what an external model is reading on their machine is the point; `--quiet` hides it.
X6 (M3 binding by default) Reject as default — see K8 below (product-owner requirement: one command in any repo).
   Compromise: per-tunnel local lock with takeover prompt; startup banner names the served repo; a notice when the
   profile last served a different repo; stable repo id (dir name + short hash of the root commit / path) in server
   instructions-independent `@meta` of every result and in `repo_overview`, so a conversation can detect a switch;
   opt-in binding (`repochat setup --bind` records the repo for that profile; bound profiles are auto-selected and
   refuse other repos); README: create a PERSONAL plugin — everyone who can use the plugin reads whatever is served.
X7 (M5 reversible ids for non-UTF-8 names) Reject. Paths that are not valid UTF-8 or contain control characters are
   unsupported: withheld under category "unsupported-name" and counted, never silently rewritten.
X8 (D15 real tunnel-client + mock control plane) Accept in principle: implemented as an opt-in integration test
   (skipped when no binary is supplied); whether it actually ran here is reported truthfully (needs the product owner's
   permission to download a 29.6 MB binary).
